# @cuckoo/db

Schema, migrations and database client for Cuckoo: Drizzle ORM on `pg` (node-postgres).
See [ADR-0002](../../docs/adr/0002-orm-and-date-library.md) for why.

## Usage
```ts
import { bookings, createDatabase, rangeOverlaps } from '@cuckoo/db';

const { db, close } = createDatabase(process.env.DATABASE_URL!);
const busy = await db
  .select()
  .from(bookings)
  .where(rangeOverlaps(bookings.during, from, to));
await close(); // on shutdown
```

`db` speaks `Date` (what `pg` returns for `timestamptz`); convert to Temporal at the edge of
`packages/core`.

## Bookings and double booking
- `start_at` / `end_at` are `timestamptz`; `during` is generated by Postgres as
  `tstzrange(start_at, end_at, '[)')`. Never write `during`.
- `bookings_valid_range`: `CHECK (end_at > start_at)`.
- `bookings_no_overlap`: `EXCLUDE USING gist (owner_id WITH =, during WITH &&) WHERE (status <> 'cancelled')`.
  Back-to-back bookings are allowed (half-open range); cancelled bookings free their slot.
- Buffers are **not** in the stored range; the slot engine enforces them.

Error codes the API should map:

| Case | SQLSTATE | Constraint |
| --- | --- | --- |
| Overlapping booking for the same owner | `23P01` | `bookings_no_overlap` |
| `end_at = start_at` | `23514` | `bookings_valid_range` |
| `end_at < start_at` (range constructor fails first) | `22000` | none |

Drizzle wraps driver errors in `DrizzleQueryError`; the `pg` error is in `.cause`.

## Ownership and auth tables
- Every owned row carries `owner_id`. Composite foreign keys (`(x_id, owner_id)`) make it
  impossible for an event type, booking or calendar to reference another owner's schedule,
  event type or connection.
- Configuration (schedules, event types, connections, sessions) is deleted with its user.
  Bookings are not: deleting a user with bookings fails (`23503`) until the account-deletion
  flow has cancelled them and notified guests.
- Auth tables follow Better Auth's models (ADR-0004). `sessions.token_hash` holds a SHA-256
  hash, never the raw token; `verifications.identifier` is hashed by Better Auth.
- `deleteExpiredAuthRecords(db)` removes expired sessions and verifications; the worker runs it
  on a schedule.

## Migrations
- Change `src/schema.ts`, then `pnpm db:generate --name=<what_changed>` and review the SQL.
- Things Drizzle cannot model (extensions, exclusion constraints) go in a custom migration:
  `pnpm db:generate --custom --name=<what>`, then write the SQL by hand with a comment saying why.
- Apply with `pnpm db:migrate` (reads `DATABASE_URL` from `../../.env` or the shell), or call
  `runMigrations(db)` from code.
- Never use `drizzle-kit push` on a shared or production database: it bypasses the
  migration history and does not know about hand-written constraints.
- `pnpm db:check` validates the migration history.

## Tests
`pnpm test:integration` runs against real PostgreSQL. Each run creates a throwaway
`cuckoo_test_*` database on the server in `TEST_DATABASE_URL` (default `DATABASE_URL`),
migrates it, and drops it at the end. Start Postgres first: `docker compose up -d --wait db`.
